# Informal Request

Make the README teach a natural product-discovery experience rather than a
catalog of expert-only commands. A newcomer should begin with `$product-talk`,
understand that the harness recommends the next useful step, and see that the
specialist skills are optional tools for deeper work. Use a familiar appointment
booking example without introducing opaque IDs before the harness creates and
lists them. After updating the README, audit all product skills against this
promise and record whether their protocols actually guide users or assume they
already know the workflow.
